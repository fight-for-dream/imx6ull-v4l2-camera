# 第六阶段：明确设置帧率，再连续采集

第五阶段在单独打开摄像头的进程里查询到 30 fps；第三阶段采集程序测得
19.40 fps。两个程序没有在同一个打开周期内运行，所以还不能据此判定原因。

本阶段沿用第三阶段的缓冲区循环，只新增两件事：

1. 在同一个程序中调用 `VIDIOC_S_PARM`，请求 20 或 30 fps，并打印驱动接受的档位。
2. 在采集 100 帧时，分别计算含首帧等待的整体速率、首帧到末帧的稳定速率，
   并统计驱动报告的序号跳跃。

在 Ubuntu 中进入本目录执行 `make`。将程序传到开发板后依次运行：

```sh
./v4l2_capture_fps /dev/video1 20
./v4l2_capture_fps /dev/video1 30
```

程序仍采用 MJPG 640×480，每次运行独立采集 100 帧，不写入图像文件。
比较两次输出时，先看驱动实际接受的帧间隔，再看“Between first and last frame”
和“Sequence gaps”。如果请求 30 fps 却仍只有约 20 fps，再继续排查设备或传输路径。
