# 第九阶段：LCD 预览、抓拍和浏览器实时查看

同一帧 MJPG 现在有三个去处：

```text
V4L2 摄像头 ─┬─ libjpeg 解码 → LCD 实时预览
             ├─ 输入 s 回车 → /tmp 中的 JPEG 抓拍
             └─ 网络线程 → HTTP MJPG 流 → 浏览器
```

`main.c` 仍负责摄像头循环。`http_server.c` 开一个独立线程，只保留最新一帧的
压缩数据；网络客户端发送得慢时，旧帧会被新帧覆盖，摄像头不必等待发送完成。
摄像头缓冲区被重新入队前，网络线程已经拿到了自己的数据拷贝。

首版只支持**一个浏览器客户端**，监听 8080 端口的 `/stream` 路径。
没有账号和加密，只适合可信的实验局域网；不应暴露到公网。
输入 `s` 回车仍可抓拍，输入 `q` 回车或按 Ctrl+C 退出。

## 编译与测试

在 Ubuntu 中进入本目录执行 `make`。将可执行文件传到开发板后，在有交互输入的
串口或 ADB 终端运行：

```sh
./camera_mjpeg_server /dev/video1 /dev/fb0
```

先用 ADB 端口转发验证网络功能，无需修改开发板 IP。保持程序运行，在 Ubuntu
另一个终端执行：

```sh
adb forward tcp:8080 tcp:8080
```

然后在 **Ubuntu 虚拟机的浏览器**打开 `http://127.0.0.1:8080/stream`。
结束测试可执行 `adb forward --remove tcp:8080` 清理端口转发。
若 LCD 与浏览器都能持续更新，再测试抓拍及客户端断开、重新连接。

此阶段只建立基本数据链路；后续还要验证长期运行、摄像头拔插恢复、网络慢客户端
行为以及实际帧率和 CPU 占用。第八阶段和之前的已验证文件保持原样。
