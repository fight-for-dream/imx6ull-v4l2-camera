# 第三阶段：连续采集

前两阶段已经确认 `/dev/video1` 支持 MJPG 和 streaming，并成功保存一帧 JPEG。
这一阶段不保存图片，只连续读取 100 帧，观察缓冲区如何循环使用，并计算平均帧率。

在 Ubuntu 中进入本目录后执行 `make`。将生成的程序传到开发板，再运行：

```sh
./v4l2_capture_loop /dev/video1
```

程序的核心循环只有三件事：

1. `poll` 等待驱动填好一帧。
2. `VIDIOC_DQBUF` 取出已填好的缓冲区，读取这一帧的大小和序号。
3. `VIDIOC_QBUF` 将同一缓冲区交还驱动，以便下一帧继续使用。

可以把缓冲区想成反复借用的容器：

```text
程序交出空缓冲区 --QBUF--> 驱动填入一帧 --DQBUF--> 程序读取 --QBUF--> 驱动继续使用
```

`mmap` 只是让程序能访问这些缓冲区；它本身不会取出一帧。若取出后不重新入队，
驱动最终会没有空缓冲区可用，连续采集就无法继续。

程序请求 MJPG 640×480，并打印实际采用的尺寸。默认读取 100 帧，
可以修改源码开头的 `FRAME_COUNT`。它每 20 帧打印一次进度，避免终端输出影响采集速度。
结束时输出总耗时和程序实际接收的平均帧率。计时使用不受系统校时影响的
`CLOCK_MONOTONIC`；`STREAMOFF`、`munmap` 和 `close` 负责释放资源。
